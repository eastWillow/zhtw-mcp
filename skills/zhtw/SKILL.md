# Traditional Chinese (Taiwan) writing validation

Use the installed zhtw-mcp server's zhtw tool to check Taiwan vocabulary,
punctuation, spacing, and character forms. Discover the available MCP tool
instead of assuming a client-specific tool prefix.

## Prerequisite

The zhtw-mcp executable must be installed on the PATH inherited by the client
(Codex or Claude Code).
If the server is unavailable, report the missing prerequisite and point to
the repository's installation instructions. Do not claim validation passed
without a tool result.

## Workflow

1. Read the text the user wants reviewed. Preserve code, quoted material,
   product names, and the user's intended meaning.
2. Call zhtw with the original text, profile base, and fix_mode none.
   Set content_type to markdown for Markdown so fenced code and inline
   code are excluded. Use plain for ordinary prose and UI strings.
3. If the user requested corrections, call with fix_mode lexical_safe
   and output full to obtain the corrected text. Review the returned
   corrections before applying them to the user's file. For a review-only
   request, explain the findings without changing files.
4. Discuss contextual findings that remain. Do not apply lexical_contextual
   corrections automatically; inspect their context and use that mode only
   when the user's requested editing scope supports the change.
5. After editing, check the resulting text with fix_mode none and
   max_errors 0. Add max_warnings 0 only when the user requires a gate
   that rejects warnings too. Inspect accepted and report unresolved
   findings; a warning-free result is not implied by max_errors 0.

For example, a deterministic Markdown correction request is:

```json
{
  "text": "這個軟件使用默認配置。",
  "content_type": "markdown",
  "profile": "base",
  "fix_mode": "lexical_safe",
  "output": "full"
}
```

## Choosing options

- Use profile base for ordinary writing. Use strict when the user requests
  full Ministry of Education character-form and punctuation enforcement.
- For UI strings, use relaxed true with profile base. Relaxed is a boolean,
  not a profile name.
- For AI-generated prose, use detect_ai true. Enable detect_translationese
  when reviewing translated prose; both are boolean capabilities.
- Use output compact for follow-up checks when corrected text is not needed.
- Omit verify unless the user requests online verification, the tool schema
  advertises it, and the user accepts sending the supplied text to Google
  Translate. Ordinary linting and lexical_safe correction do not require
  that external verification.

Each call is stateless. Repeat the relevant options on subsequent calls.

## Resources

Read zh-tw://style-guide/moe for Taiwan Ministry of Education conventions.
Read zh-tw://dictionary/ambiguous when assessing cross-strait terms whose
appropriate translation depends on context. When a resource or sampling
capability is unavailable, retain the uncertainty in the review.
